# Build-Time Data Provenance and Licensing

Every file in this directory is a **build-time input** read by
`crates/pdftract-core/build.rs` to generate Rust tables (std14 metrics, named
encodings, AGL maps, font fingerprints, predefined CMaps, glyph names, English
wordlist). Despite the directory name, none of it is generated *by* a build —
it is committed source data. The blanket root `.gitignore` rule `build/` has
explicit negations (`!crates/pdftract-core/build/`,
`!crates/pdftract-core/build/**`) so git cannot silently hide any of it:
if a file here is modified or added it shows up in `git status` like any other
source.

Integrity is enforced by the TH-06 supply-chain gate (`build.rs`
`verify_checksums()`): `CHECKSUMS.sha256` pins the SHA-256 of every tracked
input and is verified on every build of `pdftract-core`. Pinned paths are
resolved relative to this directory. A corrupted or tampered input fails the
build with a per-file message naming the offending path; a *deleted* pinned
input fails with `pinned in CHECKSUMS.sha256 but missing` (deletion is not
treated as an optional absence); a deleted `CHECKSUMS.sha256` fails with a
targeted `CHECKSUMS.sha256 not found` error.

## File inventory

| File | Origin | License / redistribution |
|---|---|---|
| `std14-metrics.json` | Generated by `generate_std14_metrics.py` (tracked, this dir) from Adobe AFM metric data for the Standard 14 fonts (PDF 1.7 Annex D.4/D.5). | Font metric data from Adobe's freely redistributable AFM files. |
| `named-encodings.json` | Transcribed from the predefined encodings in ISO 32000-1 Annex D (WinAnsi, MacRoman, MacExpert, Standard, Symbol, ZapfDingbats). | Specification data (ISO 32000-1, publicly available Annex D tables). |
| `agl.json` | Generated by `generate_agl.py` (tracked, this dir) from `aglfn.txt` (AGLFN 1.7) and `glyphlist.txt` (Adobe Glyph List 1.4), both tracked in this dir. | Adobe, 2002-2019; BSD-style redistribution license stated in each file header. |
| `font-fingerprints.json` | Manually curated from open-source fonts (Roboto, Apache License 2.0) by the maintainer-owned pipeline described in `docs/notes/font-fingerprinting.md`. | Derived from Apache-2.0 font programs; database is project-authored. |
| `predefined-cmaps/*.json` | CID→Unicode mappings for the `adobe-japan1`, `adobe-gb1`, `adobe-cns1`, `adobe-korea1` character collections, derived from Adobe's character-collection CMap resources. | Adobe CMap resources are freely redistributable per their license notices. Regeneration tooling is not currently tracked (see below). |
| `unmapped-glyph-names.json` | Project-authored configuration listing glyph names skipped during CMap/ToUnicode entry creation. | Project-original. |
| `wordlist-en-20k.txt` | Frequency-sorted 20k English word list from the `google-10000-english` project. | MIT. |
| `CHECKSUMS.sha256` | Project-authored integrity manifest (bead `pdftract-1xf4d`, plan TH-06). | Project-original. |

The tracked generator scripts (`generate_std14_metrics.py`,
`generate_agl.py`, `fix_std14_weights.py`) and raw sources (`aglfn.txt`,
`glyphlist.txt`) make the JSON inputs reproducible from tracked material.

## Optional: glyph-shapes.json (not tracked, not pinned)

`glyph-shapes.json` is the **optional** Level 4 glyph-shape recovery database.
It is produced by rasterizing glyphs from a developer-supplied fonts directory:

```sh
cargo xtask gen-shape-db <fonts-dir>
# writes crates/pdftract-core/build/glyph-shapes.json (default output path)
```

It is intentionally **not** tracked and **not** pinned in `CHECKSUMS.sha256`:
its content depends on which font binaries are supplied, so it is not
reproducible from tracked source, and its absence only disables Level 4
recovery (empty `SHAPE_TABLE`/`FREQ_TABLE`, `cargo:warning` at build time) —
never a build failure. `build.rs` reads it from this directory (crate-relative
`build/glyph-shapes.json`), the same tracked, unignored location as every
other input, so a locally generated copy appears in `git status` rather than
being silently swallowed by an ignore rule.

## Regenerating CHECKSUMS.sha256

After a legitimate change to any tracked input:

```sh
cd crates/pdftract-core/build
sha256sum std14-metrics.json named-encodings.json agl.json \
  font-fingerprints.json wordlist-en-20k.txt unmapped-glyph-names.json \
  predefined-cmaps/*.json > CHECKSUMS.sha256
```

`build.rs` aborts with the same regeneration recipe if a checksum ever
mismatches. Do not add an entry for a file that is not tracked in git — a pin
for a path a fresh clone does not have is dead weight (that was the
`../../../build/glyph-shapes.json` entry removed with this note).

## Verification — clean clone

From a fresh clone (or any `git archive HEAD` extraction, which contains only
tracked files — stricter than a clone because ignored local artifacts are
absent too):

```sh
git archive HEAD | tar -x -C /tmp/pdftract-clean && cd /tmp/pdftract-clean
cargo check -p pdftract-core --lib        # must pass with no preparatory steps
```

Expected: success. A `cargo:warning` about `glyph-shapes.json not found` is
expected and benign (optional input). Any checksum failure is a real integrity
problem, not a missing-setup problem.

## Verification — corruption detection

Corrupting a required input, deleting one, or deleting the manifest must each
produce a targeted failure:

```sh
# corrupt an input in the extraction
printf 'x' >> crates/pdftract-core/build/agl.json
cargo check -p pdftract-core --lib 2>&1 | grep -i checksum   # build fails naming agl.json

# delete a pinned input
git checkout -- crates/pdftract-core/build/agl.json
rm crates/pdftract-core/build/wordlist-en-20k.txt
cargo check -p pdftract-core --lib 2>&1 | grep "pinned in CHECKSUMS.sha256 but missing"

# delete the manifest
git checkout -- crates/pdftract-core/build/wordlist-en-20k.txt
rm crates/pdftract-core/build/CHECKSUMS.sha256
cargo check -p pdftract-core --lib 2>&1 | grep -i "CHECKSUMS.sha256 not found"
```

## Verification — package

`cargo package` must include the inputs and the unpacked package must compile
(this is what release automation and `cargo publish` consumers see):

```sh
cargo package -p pdftract-core --list | grep 'build/'      # inputs present in the package
cargo package -p pdftract-core --no-verify --allow-dirty   # then compile the unpacked crate:
mkdir /tmp/pkg && tar -xzf target/package/pdftract-core-*.crate -C /tmp/pkg
cd /tmp/pkg/pdftract-core-*/ && cargo check --lib           # must pass
```
