# Bead bf-407xp6: Calculate glyph bitmap dimensions from bounds

## Summary

Fixed test expectations for `calculate_bitmap_dimensions` function to match actual mathematical calculations from glyph bounding boxes.

## Changes Made

### File: `crates/pdftract-core/src/font/type3_rasterizer.rs`

**Problem:** Test expectations were incorrect - they claimed bbox `[10.0, 20.0, 50.0, 60.0]` represented a "40x30 point" glyph, but it actually represents a "40x40 point" glyph (60.0 - 20.0 = 40.0, not 30.0).

**Fix:** Updated three test cases with correct expected values:
1. `test_calculate_bitmap_dimensions_basic`: Fixed height expectation from 32 to 42
2. `test_calculate_bitmap_dimensions_with_custom_padding`: Fixed height expectation from 34 to 44
3. `test_calculate_bitmap_dimensions_no_padding`: Fixed height expectation from 30 to 40

## Implementation Details

The `calculate_bitmap_dimensions` function (lines 81-118) already correctly implements:

1. **Takes glyph bounding box:** `bbox: &[f32; 4]` representing `[x0, y0, x1, y1]`
2. **Calculates dimensions:** `width = x1 - x0`, `height = y1 - y0`
3. **Handles degenerate cases:** Zero-width or zero-height bboxes default to 1 pixel
4. **Adds padding:** Optional padding (default 1 pixel) for anti-aliasing margins
5. **Returns usize:** `(width, height)` as `usize` for array indexing
6. **Non-zero guarantee:** Ensures minimum dimensions of 1x1
