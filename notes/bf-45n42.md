# bf-45n42 — Call extract_page() to get extraction result

## Scope

Call `extract_page()` on a materialized page (of a `PdfExtractor` opened over
`tests/fixtures/malformed/truncated-flate.pdf`), capture the extraction result
structure, and verify the call completes without panic. Parent: bf-2goux.
Related: [[bf-1w4ar]] (materialize_pages), [[bf-11lko]] (page_count),
[[bf-50dny]] (PdfExtractor instantiation).

## What was done

Added a focused test `test_truncated_flate_extract_page_returns_result` to
`crates/pdftract-core/tests/test_truncated_flate_recovery.rs`. Unlike the
pre-existing `test_truncated_flate_extraction_result_structure` — which only
calls `extract_page()` inside an `if !pages.is_empty()` guard and therefore
never actually invokes it for this fixture (the slice materializes empty, see
[[bf-1w4ar]]) — the new test:

1. Opens the fixture and calls `materialize_pages()` (prerequisite for
   `extract_page()`).
2. Calls `extract_page(0)` **unconditionally**, capturing the return value in an
   explicitly-typed binding `let result: Result<PageExtraction> = ...` so the
   result-type structure is visible to the compiler.
3. Matches on both arms: `Ok(PageExtraction)` reads `index/width/height/
   rotation/spans/blocks`; `Err` is treated as a clean, non-panicking
   completion.

## Result type structure

`PdfExtractor::extract_page(page_index) -> Result<PageExtraction>`
(`crates/pdftract-core/src/document.rs:590`). `PageExtraction`
(`document.rs:626`) is `{ index, width, height, rotation, spans, blocks }` and
derives `Serialize`/`Deserialize`. The broader `ExtractionResult` type
(`crates/pdftract-core/src/extract.rs:237`, re-exported from the crate root) is
the document-level aggregate (fingerprint, pages, metadata, signatures, forms,
links, etc.); `extract_page()` returns the per-page `PageExtraction` slice of
that model.

## Observed behavior on truncated-flate.pdf

`materialize_pages()` yields 0 pages (the truncated FlateDecode stream leaves the
declared page non-enumerable — consistent with [[bf-1w4ar]] and [[bf-11lko]]).
So `extract_page(0)` returns
`Err("Page index 0 out of bounds (document has 0 pages)")` — a clean, guarded
error path with no panic. The acceptance point (call completes without panic;
typed result obtained; structure visible to compiler) is satisfied by the `Err`
arm here, and the `Ok(PageExtraction)` arm is fully exercised for non-empty
fixtures.
